# Plan Tracker — Audit 2026-05-09 Rollout

Tracks execution of the risk-tiered plan from [`deep-audit-2026-05-09.md`](./deep-audit-2026-05-09.md).

**Workflow** (umbrella branch model):
- All tier work lands on `plan/audit-2026-05-rollout` first.
- Each tier item is its own **sub-branch off `plan/audit-2026-05-rollout`** (e.g., `plan/audit-2026-05-rollout-A1`); PRs target `plan/audit-2026-05-rollout`, not `main`.
- The umbrella branch merges to `main` at logical milestones — recommended cadence: **after each tier completes** (one merge for Tier A, one for Tier B, one for Tier C) rather than one giant 90-day merge.
- Periodically rebase or merge `main` → `plan/audit-2026-05-rollout` so drift stays small.

**One concern worth surfacing now**: under a pure umbrella, the Tier A security-sensitive fixes (action SHA-pinning, error sanitization at registry boundary, SBOM/cosign) won't reach production until the umbrella merges. If that timeline is &gt;2-3 weeks, consider promoting individual Tier A items (A1, A2, A4 in particular) to direct-to-main PRs and only umbrella-track Tier B and Tier C. Owner call.

**Tier D items are intentionally absent** — they were retracted after fact-check.

## Conventions for tier-rollout PRs (umbrella model)

1. **One tier item = one sub-branch + one PR**, regardless of LOC. Sub-branch off `plan/audit-2026-05-rollout`; PR targets `plan/audit-2026-05-rollout`.
2. **Sub-branch name format**: `plan/audit-2026-05-rollout-A1` (suffix the tier ID).
3. **PR title format**: `feat|fix|chore(scope): A1 — short description (audit-2026-05)`. The `A1` / `B2` / `C3` tag makes the tracker auto-greppable.
4. **PR body must reference** this tracker + the original reviewer slice (e.g., "closes Tier A1; source: Reviewer E P0 #4").
5. **Tier B PRs must include**: a flag name, default value, and a "how to revert" line.
6. **Tier B PRs must show** before/after measurement evidence (recall@k delta, token cost, latency p50/p95, error rate — whichever applies).
7. **Tier C PRs must show** a full green test run on each extracted module (no behaviour changes allowed in extract PRs).
8. **Umbrella → main merges**: at the end of each tier (or earlier if Tier A is held back beyond 2-3 weeks), open a PR `plan/audit-2026-05-rollout` → `main`. Cherry-pick to main is also fine for urgent security items.
